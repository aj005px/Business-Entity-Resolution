Read this before using the number. F0.5 = 0.9082 is a validation score measured on a held-out 20% split of the 200,000 blocked training queries. The test split is unlabelled, so the score the submission actually receives is not known. F0.5 weights precision twice as heavily as recall, which is why the operating point sits at a high threshold of 0.950.

The model is almost entirely an address matcher. addr_token_jaccard alone carries 55% of the total gain; name similarity features contribute a small fraction in comparison. country_match scores exactly zero because country is already a hard filter inside blocking, which makes the feature constant across every surviving candidate. Both are worth revisiting if the model is extended.

Threshold sweep

F0.5 rises monotonically as the threshold climbs because precision is weighted double. The chosen operating point (0.950) is the highest threshold in the sweep and still yields 0.8468 recall, which sits just under the 0.8657 blocking ceiling — the classifier captures 97.9% of everything blocking allows.

Known limitations

  • Blocking recall ceiling is 86.57%, not the 96.7% the README claims. 13.4% of true pairs are never generated as candidates, so no classifier can recover them — this hard-caps achievable recall. Measured on a slice verified as representative (country mix 59.9/40.2 vs 60.0/40.0, mean name length 26.29 vs 26.27 chars), so it is not a sampling artifact.
  • Only 9.06% of the train split was blocked. With 18 features and 400 trees the learning curve is flat well before 1M rows, so this costs very little accuracy — but it is a real coverage gap, and it was a deliberate trade to fit the time budget.
  • Test feature coverage is 29.9%. This is the single biggest gap in the deliverable.
  • Train and test blocking used different token thresholds (0.02 vs 0.008 document frequency) to buy a 2.5× speedup for 0.6 pt of recall. The resulting candidate sets differ by 0.3% of pairs.
  • The model is address-dominated and country_match is inert, as described above.
